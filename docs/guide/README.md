# LoongPort 使用指南

从第一次安装，到连接服务、切换模型、自动故障切换、查看用量和恢复配置。

**适用版本：稳定版 v6.26.2。** ZCode 单独标注为 **v6.26.3-beta.2 测试版**。本指南按实际版本中的按钮编写，不把计划中的功能当作已提供功能。

> 图片中的服务、账号、余额和使用量全部是演示数据。截图由对应发布版本的真实界面组件在隔离演示环境中渲染；不是实际账号登录、付费调用或原生配置写入成功的证明。`example.com` 是示例域名，不能用来调用模型。请在自己电脑上换成可信服务商提供的地址和凭据。

## 1 安装前要准备什么

### 1.1 先分清三个东西

- **应用**：你真正与 AI 对话的工具，例如 Codex 或 Claude Code
- **服务与账号**：提供模型访问的服务及你在该服务的账号，可以是官方 API 或兼容的中转站
- **档位**：该账号下可用的一套访问配置；不同档位可能有不同模型、价格、倍率和限额

LoongPort 帮你管理这些配置，并在需要时通过本机的本地路由转发请求。它不是模型，也不替你购买服务；服务商账号、额度和使用条款仍由对应服务商管理。

**最少需要准备：** 一台支持的电脑、一个已安装并运行过的 AI 应用，以及一份你有权使用的服务访问权限。只安装 LoongPort，不等于已经安装 Codex 或 Claude Code。

### 1.2 下载正确的安装包

从 [LoongPort 官方下载页](https://loongport.dev/zh/download) 或 [官方 GitHub Releases](https://github.com/SailingLoong/LoongPort/releases) 下载。初次使用优先选稳定版；不要因为测试版的版本号较大就直接选它。

| 你的系统                                    | v6.26.2 对应文件                            | 选择建议                                    |
| ------------------------------------------- | ------------------------------------------- | ------------------------------------------- |
| Windows 10 或更高，普通 Intel/AMD 电脑      | `LoongPort-v6.26.2-Windows-Setup.exe`       | 推荐安装版；按安装向导完成                  |
| Windows ARM64 电脑                          | `LoongPort-v6.26.2-Windows-arm64-Setup.exe` | 不要误选普通 x86_64 包                      |
| Windows，明确需要免安装                     | 对应架构的 `Windows-Portable.zip`           | 解压后运行；更新时下载新压缩包              |
| macOS 12 或更高                             | `LoongPort-v6.26.2-macOS.dmg`               | Intel 与 Apple Silicon 通用；拖入“应用程序” |
| Linux x86_64，Ubuntu 22.04 或相近的新发行版 | `LoongPort-v6.26.2-Linux-x86_64.AppImage`   | 赋予可执行权限后启动；运行环境需要支持 FUSE |
| Linux，使用发行版包管理器                   | 对应 `.deb` 或 `.rpm`                       | 由包管理器安装；不使用应用内原地更新        |

Linux 桌面版需要 WebKitGTK 4.1 和合适的 glibc。无桌面服务器、Ubuntu 20.04 等旧系统请看 [LoongPort CLI 指南](../loongport-cli.md)，不要在服务器上反复尝试桌面安装包。

macOS 版本目前未经 Apple 签名与公证。若系统阻止打开，先核对来源、文件是否完整及官方发行说明；按 [下载页](https://loongport.dev/zh/download) 的针对性说明处理。不要关闭整台电脑的安全保护，也不要运行陌生网站提供的“修复”脚本。

**这一步完成的标志：** LoongPort 能打开窗口，没有安装或运行库错误。首次打开可能先要求解锁凭据保护，见 [6.1](#61-语言外观与凭据保护)。

### 1.3 先初始化要使用的应用

1. 按目标应用的官方说明安装 Codex 或 Claude Code
2. 新开一个终端，运行 `codex --version` 或 `claude --version`，确认能显示版本
3. 在一个你允许 AI 使用的文件夹中启动该应用一次，完成它自己的初始化
4. 暂时退出该应用，再打开 LoongPort

不要把别的工具或公司项目文件夹当成“练习目录”。第一次测试可使用自己新建的空文件夹。

如果应用不存在或配置目录尚未初始化，LoongPort 可能提示“尚未找到应用配置，请先启动应用完成初始化”。这不是让你重新购买 API，也不是让你删除配置文件。

### 1.4 认识主界面

![应用工作台：主导航、应用选择与档位列表](images/01-application-workspace.png)

图中 ① 先选择要管理的应用；② 添加服务；③ 核对当前档位；④ 自动故障切换开关；⑤ 鼠标移到目标行后可点“设为当前”。

- **应用**：决定正在管理哪个应用，查看当前档位、切换和安排备用顺序
- **服务与账号**：集中查看已连接的服务，处理登录、刷新、余额和账号配置
- **生图**：使用生图档位生成图片，或设置给 CLI 使用的生图工具
- **使用记录 / 用量**：分别查会话历史、请求与费用
- **扩展资源**：MCP、Skills、Prompts、统一供应商及特定应用的工作区工具
- **中转站广场**：浏览可接入的站点，也可输入自己的服务网址。设置控制推荐列表的显示，不会移除广场入口或网址输入能力
- **设置**：语言、应用显示、连接、认证、备份和更新

应用栏没有你要用的工具时，打开“更多应用”或应用栏的添加入口；也可到“设置 → 通用 → 主页面显示”开启。显示一个应用入口不会替你安装该应用。

## 2 让第一个应用成功对话

目标：先让一个应用、一个服务、一个档位跑通。第二个服务和自动故障切换稍后再加。

### 2.1 选择接入方式

点击 **添加服务**，根据你已经有什么选择一条路：

| 你手里已有的东西                                    | 选择                                      |
| --------------------------------------------------- | ----------------------------------------- |
| 中转站网址和该站账号                                | **中转站**，按 2.2 操作                   |
| DeepSeek、智谱 BigModel 或 opencode 的官方 API 账号 | **官方 API**，按 2.3 操作                 |
| 服务商给出的 API 地址、API Key、模型 ID             | **手动添加**，按 2.4 操作                 |
| 已在 cc-switch 配好，想迁移                         | 先备份，再看 [6.3](#63-从-cc-switch-迁移) |

![添加服务：中转站、官方 API、手动添加三种入口](images/06-add-service.png)

图中 ① 按现有账号/Key 选择接入方式；② 输入服务网址；③ 打开该服务的注册或登录页面。

### 2.2 用中转站账号接入

**先准备：** 可信服务商的网址、你在该站的账号，以及至少一个有额度且允许使用的档位。

1. 首次向导名为 **连接你的第一个服务**。在“中转站网址”中填该服务的地址。演示写作 `https://example.com`，实际请用自己的服务地址
2. 点击 **进入注册 / 登录**
3. 确认打开的页面域名确实属于所选服务。已有账号就登录，没有账号再按该服务的规则注册
4. 登录完成后，回到 LoongPort 的 **确认应用配置** 页面
5. 为这次要用的应用选择一个可用配置，其它应用先保留 **暂不配置**
6. 查看“分享服务使用与实测数据”及“了解分享内容”。这是可选项，不勾选也能使用；按自己的意愿选择
7. 点击 **完成设置**

![首次连接：填写自己的服务网址](images/10-first-service.png)

图中 ① 服务网址，实际要替换 example.com；② 官方 API / 广场可选入口；③ 进入所选站点。

![确认应用配置：选目标应用、档位和可选分享项目](images/11-confirm-application.png)

图中 ① 不使用的应用保留“暂不配置”；② 为目标应用选档位；③ 阅读可选数据分享并自行选择；④ 完成设置。

LoongPort 会根据服务提供的信息获取可用档位，并按支持的配置格式写入你选择的应用。某些服务会涉及创建或复用 API Key；操作对象始终是你选定的服务账号。

**成功的标志：** “服务与账号”里出现该账号，“应用”页能看到档位和当前配置。然后一定继续完成 [2.5 的真实对话测试](#25-验证真的能用)。

**如果没有成功：**

- 关闭了登录窗口：重新点击进入注册 / 登录即可，不要重复注册账号
- 账号已保存但没有可用配置：检查该服务的额度、订阅、分组权限和模型支持，再刷新账号
- 提示站点不兼容：确认是否为受支持的 sub2api / new-api 服务；已有 API Key 时可检查“手动添加”是否适合，不能保证任意网站都能自动登录
- 已登录却仍显示登录过期：从“服务与账号”对该账号重新登录；不要把密码、Cookie 或登录响应发到公共 Issue

### 2.3 用官方 API 账号接入

1. 点击 **添加服务 → 官方 API**
2. 选择页面实际列出的厂商：DeepSeek、智谱 BigModel 或 opencode
3. 在该厂商的真实页面完成登录
4. 回到 **确认应用配置**，为目标应用选配置，再点 **完成设置**
5. 按 [2.5](#25-验证真的能用) 测试

“官方 API”指厂商 API 服务，不等于 ChatGPT、Claude 等聊天产品的订阅。API 计费、套餐和可用模型以该账号实际权限为准。opencode 账号可能显示不同套餐配置，请选择自己有权使用的那一项。

### 2.4 只有 API Key：手动添加

**先准备这四项，缺一项先向服务商确认：**

| 字段     | 演示值                        | 实际应填什么                                          |
| -------- | ----------------------------- | ----------------------------------------------------- |
| 名称     | `演示服务`                    | 自己能认出的名称                                      |
| API 地址 | `https://api.example.com/v1`  | 服务商给目标应用的完整 Base URL；不要凭经验乱加 `/v1` |
| API Key  | `REPLACE_WITH_YOUR_API_KEY`   | 该服务生成的密钥；不把示例文字原样保存                |
| 模型 ID  | `MODEL_ID_FROM_YOUR_PROVIDER` | 服务商模型列表里确切的 ID；显示名称未必等于 ID        |

1. 先在应用栏选择要配置的应用，例如 **Codex**
2. 点击 **添加服务 → 手动添加**
3. 首次出现“关于通用配置”说明时，阅读后点 **我知道了**。有对应预设就选预设，否则选 **自定义配置**
4. 填名称、API 地址、API Key 和模型信息；不同应用的表单不完全相同
5. 检查服务支持的 API 协议。OpenAI Responses、Chat Completions、Anthropic Messages 不能只看名字相近就混用
6. 保存后返回“应用”，在新增档位上点 **设为当前**
7. 按下一节重新启动目标应用并测试

![手动添加供应商：先选择目标应用，再填写该应用所需信息](images/07-manual-provider.png)

图中 ① Key 由你本人填入，不用截图中的占位提示；② 核对 API 请求地址；③ 改成服务确实支持的模型；④ 上游格式要与服务接口匹配。图中未填写密钥，也没有保存或调用服务。

**不要做：** 不要把教程中的 JSON 整份覆盖到已有配置文件；不要在公开聊天、截图或 Git 中粘贴真实 Key。表单里有“配置内容”并不表示小白必须手写 JSON；优先使用现有表单和预设。

### 2.5 验证真的能用

1. 回到 **应用**，确认应用名称正确，预期档位标着 **当前**
2. 退出并重新启动目标 CLI。Codex 相关配置也可能影响共用配置的桌面应用；若弹出退出/重启确认，先保存正在进行的工作，再按提示选择
3. 在目标应用发送一句不含任何私人数据的话，例如：`请用一句话介绍你能做什么`
4. 看到正常回复后，再开始自己的任务
5. 开启本地路由时，还可在“用量”查看相应请求记录；这用于进一步核对，不代替实际回复

**以下都不能单独证明成功：** 登录成功、出现“已保存”、档位有“当前”标记、余额不为零。它们分别证明不同阶段完成，真正可用仍要看目标应用能否发出并完成请求。

出现 `401/403`、模型不存在或连接失败，直接看 [6.6 排障表](#66-按现象排障)。不要为了排障连着创建许多新 Key。

## 3 让故障时自动换到备用档位

### 3.1 先确认本版支持什么

**v6.26.2 的界面名称是“自动故障切换”。** 你先确定允许尝试的档位和优先级，当前请求失败时，系统按已应用列表尝试其它可用档位。

本版没有旧教程中的 **“省心 / 自主”切换**，也不提供 **“价格最低 / 响应最快”自动择优策略**。这些旧宣传不能等同于现在的自动故障切换。你仍可参考表格的倍率、错误率、首字耗时等指标，自己安排顺序。

适用于本地路由完整支持的 **Claude Code、Codex、Gemini、Grok Build**。原生登录、某些官方账号或不支持此路由方式的配置不参加自动切换，界面会显示原因。不要把“能添加此应用”理解为“此应用支持所有功能”。

### 3.2 开启一次

**前置条件：** 第 2 章已经跑通；目标 CLI 已初始化；同一模型至少有两个你愿意使用的兼容档位。只有一个档位时，开关不会凭空生成备用服务。

1. 打开 **应用**，选择目标应用
2. 在“可用档位”旁打开 **自动故障切换**
3. 如提示初始化、连接或配置问题，先处理提示。开启成功需要本地路由运行并接管这个应用的连接
4. 检查列表的优先级、当前档位以及不参与切换的原因
5. 在目标应用再发一条测试消息，确认开启后仍能正常对话

![应用工作台：自动故障切换、档位指标与优先级](images/01-application-workspace.png)

图中 ① 先选择要管理的应用；② 添加服务；③ 核对当前档位；④ 自动故障切换开关；⑤ 鼠标移到目标行后可点“设为当前”。

**成功的标志：** 开关保持开启，没有“自动故障切换已暂停”的提示，目标应用的请求仍正常。需要核对连接时，打开 **设置 → 连接设置 → 本地路由**，查看运行状态和对应应用是否已启用路由。

### 3.3 设置备用顺序，记得点“应用更改”

1. 打开自动故障切换后，点 **查看全部档位**，找到希望加入的配置
2. 需要固定模型时，用 **档位模型** 选择该模型；也可按账号筛选或搜索
3. 拖动顺序，或点击指标列排序。**数字越小越先尝试**；显示“—”的档位不参与自动切换
4. 出现 **更改尚未生效** 时，逐项核对当前可见列表
5. 点击 **应用更改**；不想改变实际配置就点 **取消**
6. 确认未生效提示消失，再做一次真实请求

![调整后出现待生效提示：检查列表，再应用或取消](images/08-pending-changes.png)

图中 ① 当前筛选条件；② 更改仍是草稿；③ 放弃本次调整；④ 核对后应用。

**这里特别容易误会：** 开启自动故障切换后，筛选、排序和选择模型可以构成待应用的调整；不是“看一看表格”就已经改变运行中的列表。点“应用更改”时还可能应用所选模型，并在需要时选择支持它的档位。提交前请检查模型、账号和列表范围。

列里的“—”表示没有数据或不适用，不是价格为零、从不失败或无限余额。表格中的余额可能是同一个账号共享的余额，不能把多行余额直接相加。

### 3.4 保存常用顺序

“可用档位”旁的 **配置档** 保存的是档位顺序，不是整台应用的备份。

1. 调整到想要的列表
2. 打开配置档菜单，点 **保存当前顺序…**，输入如“日常使用”的名称
3. 之后选择已保存的配置档，检查待应用列表
4. 按界面提示点 **应用更改**

同名保存会覆盖该顺序配置档。导入/导出顺序配置档适合迁移排序；它不会替对方创建服务账号、密钥或可用额度。没有相同档位时不能期待完整复原。

### 3.5 故障时看哪里

- **暂时跳过：等待连接恢复**：先看最近错误、服务额度和网络状态，不要连续点击重试
- **不支持当前选择的模型**：换成该档位确实支持的模型，或选择另一档
- **已屏蔽**：这是你排除的档位；确定要重新使用时才取消屏蔽
- **当前使用官方登录，不进行自动故障切换**：保留官方登录使用方式，或明确选择支持路由的 API 配置
- **自动故障切换已暂停**：点 **恢复连接**，再核对连接设置；不要把亮着的开关当成请求一定已走路由

“清除错误记录”不代表上游问题已经修复，也不是更换密钥的替代操作。优先保留错误信息，定位原因后再清理。

### 3.6 关闭自动切换，或完全恢复直连

这三种动作影响不同：

| 你想做什么               | 操作                                                    | 结果                                                 |
| ------------------------ | ------------------------------------------------------- | ---------------------------------------------------- |
| 不再故障时换档位         | 在应用页关闭 **自动故障切换**                           | 停止自动换档；本地路由和应用接管不一定关闭           |
| 仅让一个应用退出本地路由 | **设置 → 连接设置 → 本地路由 → 路由启用**，关闭对应应用 | 恢复该应用的直接配置；其它应用可继续路由             |
| 停止整个本地路由         | 同一位置关闭 **路由总开关**                             | 停止服务，并恢复已接管的配置；会影响所有依赖它的应用 |

![连接设置：路由总开关与按应用的路由开关](images/04-connection-settings.png)

图中 ① 连接设置；② 全部应用共用的路由总开关；③ 按应用启停路由；④ 本机服务地址与端口。

恢复后重新启动目标应用并测试。不要在路由仍接管时直接退出后台、删除配置或手工改端口，否则目标应用可能继续指向一个已经停止的本地地址。

## 4 日常切换模型与管理服务

### 4.1 手动换一个档位

1. **应用**中选择目标应用
2. 找到目标档位，查看服务、账号和模型是否正确
3. 点击 **设为当前**
4. 如出现退出/重启确认，先处理正在进行的工作，再选择相应操作
5. 重新启动目标应用，发送测试消息

选择新档位可能把之后的请求发送给另一家服务商。对话、代码或附件是否允许交给该服务，应由你先确认。

### 4.2 改模型：先确认服务真的支持

1. 在 **档位模型** 筛选框中选择需要的模型；总共只有一个模型时，这个筛选框不会出现
2. 只使用明确支持该模型的档位；模型名称不熟悉时先查看服务商的模型列表
3. **自动故障切换关闭时**：筛选只是查看。还要在目标档位行点击 **设为当前**，才能提交该档位和所选模型
4. **自动故障切换开启时**：检查待生效的模型与档位列表，再点 **应用更改**。不要把筛选结果当成已生效配置
5. 在目标应用确认生效模型，再发送简短测试

搜索框是查找工具，不是购买权限，也不会让不支持的模型变得可用。模型目录可能滞后；服务端返回“模型不存在”时，应以服务商实际支持范围为准。

### 4.3 连接测试与模型验证不是一回事

- **连通性/速度测试**：帮助判断请求能否完成、耗时如何；测试本身可能产生费用
- **模型验证**：在支持的托管档位上，通过有限证据帮助检查模型行为与标称是否一致；不是官方认证，也不是绝对鉴定

做模型验证时：

1. 在支持的档位操作区打开 **模型验证**
2. 选择该档位提供的模型
3. 阅读提示后开始验证，等待结果；不要重复提交同一任务
4. 查看结论和证据，有疑问时向服务商核对；需要停止时使用取消入口

没有异常标记不等于已经验证通过。“暂无数据”也不等于服务质量差。不要仅凭一次验证报告作确定性指责。

### 4.4 账号过期、刷新、充值与对账

1. 点击 **服务与账号**，选择需要处理的服务账号
2. 登录过期时重新登录；登录有效但档位变了时刷新账号
3. 需要额度时，使用该账号提供的充值入口，核对打开页面的域名、金额和套餐
4. 需要核对花费时，先检查本地“用量”，再看该站的用量/账单或 **扣费对账**

登录态过期和 API Key 失效是两件事。有的账号过期后已有 Key 仍可请求，所以不要一见登录过期就删除全部配置。

本地估算费用与服务商实际扣费可能采用不同价表或时间范围。对账时统一时间窗口，并考虑充值、其它设备调用、套餐、倍率、缓存和计价差异；不能只看一个比值就断定多扣费。

### 4.5 管理自定义配置、统一供应商与官方登录

- **编辑/复制自定义配置**：在应用页展开 **配置管理**，找到对应项。服务账号生成的托管配置应到“服务与账号”的账号详情处理，避免刷新后误以为配置被“丢失”
- **统一供应商**：到 **扩展资源 → 统一供应商**，维护可供多个应用使用的供应商配置；逐个检查目标应用、协议和模型，不把一个应用的格式照搬到全部应用
- **切换已有官方配置**：在相应应用选择已有的官方配置，并按提示重新启动。Codex 的官方凭据保护开关在“设置 → 通用”。这与下文“恢复官方登录”的重置动作不同
- **桌面应用**：Claude Desktop 的配置形状与 Claude Code 不同。先选正确应用，再使用其直连/模型映射表单；需要映射时依赖本地路由，不能把 CLI 的操作全部照搬

OpenCode、OpenClaw、Hermes、Pi 采用各自原生配置方式，可能允许多个供应商同时存在；“启用”不一定等于全局只能选一个。最终模型选择以该应用自己的界面为准。

### 4.6 管理订阅授权账号（OAuth 认证中心）

**设置 → 认证 → OAuth 认证中心** 提供 GitHub Copilot、ChatGPT（Codex OAuth）和 xAI（Grok OAuth）三个账号区。该能力在界面中标为 **Beta**，与“官方 API”账号不是一回事，也不保证任意订阅都能用于任意应用。

1. 先确认自己的订阅、用途和目标应用符合相应平台条款，再进入对应账号区
2. 点击登录/添加账号，在平台自己的授权页面完成操作。不要在第三方页面输入平台密码
3. 回到 LoongPort，确认显示的是正确账号；有多个账号时按需设置默认账号
4. 在支持该授权方式的供应商表单中选择对应账号。设置默认账号并不等于已切换目标应用的供应商
5. 标记“需要重新登录”时使用该账号的重新登录入口；不再使用时从列表移除前先检查哪些配置依赖它

成功标志是授权账号已被识别，目标配置正确绑定，并完成一次实际请求。账号列表中出现一行不能单独证明所有调用都可用。不要分享授权响应、Cookie、令牌或恢复码。

### 4.7 需要重新回到 ChatGPT 原生登录

仅在你明确需要移除 LoongPort 的 Codex 路由并重新建立官方登录时使用此操作。普通换档位不需要先做它。

1. 保存 ChatGPT 中正在进行的工作
2. 打开 **设置 → 认证 → ChatGPT（Codex OAuth）**
3. 点击 **恢复官方登录**，阅读确认内容：应用会退出 ChatGPT、移除 LoongPort 路由，并在备份后删除当前 Codex 登录状态
4. 确认后重新打开 ChatGPT，**重新登录官方账号**，再做一次测试

**Windows 特别注意：** 此操作需要强制关闭 ChatGPT，不会出现保存提醒。备份登录状态不等于以后自动帮你登录；请确保自己可以完成官方登录。

## 5 生图记录用量与扩展资源

### 5.1 在 LoongPort 里生图

**先准备：** 服务账号有可用的生图分组及额度。普通聊天档位不一定支持图片生成。

1. 添加或刷新该服务账号，让生图档位出现在 **生图** 页
2. 打开 **生图**；需要管理档位时选 **接入配置**，启用想用的档位
3. 返回 **生成**，检查 **当前接入配置**
4. 写图片描述，选择支持的尺寸、质量和张数。第一次先生成 **1 张**
5. 点击 **生成**，等待结果出现在 **生成记录**
6. 用 **在文件夹中显示** 找到实际文件

张数会影响费用，并发提交可能同时发出多次请求。请求较慢时先等待，不要反复点生成。如果只成功一部分，先保留已成功的图片，再处理失败部分。

页面没有接入配置时，检查服务是否真的提供生图分组；不要把聊天模型的名称手改成图片模型以为就能使用。

### 5.2 在 CLI 对话中调用生图工具

1. 先按上一节选好生图接入配置
2. 在“生图”页检查 **在 Codex / Claude 对话中提供生图工具**。本版默认开启；若已关闭且你需要它，再手动开启
3. 本版工具注册目标是 **Codex、Claude Code、Gemini CLI**。首次写入或重新开启后，重启你实际使用的这些 CLI，让它们重新读取工具配置
4. 在对话里明确请求使用生图工具，并核对 CLI 展示的工具确认与结果

生图配置与聊天档位各自独立，不必为了生图把正常聊天档位换掉。CLI 是否调用工具、具体权限提示以及输出位置，以当前 CLI 与页面显示为准。

### 5.3 查用量和请求错误

1. 点击左侧 **用量**
2. 先选日期范围，再按应用、供应商或模型缩小范围
3. 查看请求数、Token、费用和趋势，再打开相关请求记录看错误
4. 需要对账时记录时间、目标应用和模型；向服务商发送信息前，先去掉密钥、账号和对话内容

没有记录时先检查采集来源、日期范围和本地路由的“记录请求用量”设置。通过别的设备、未被记录的路径或不支持的应用发出的请求，不一定出现在这里。不要把空图表理解为“绝对没有消费”。

### 5.4 找回和继续一次会话

1. 点击 **使用记录 → 会话历史**
2. 选择相应应用，按标题或内容搜索
3. 选中会话，先预览确认是自己要找的内容
4. 界面提供继续会话或恢复命令时，按该应用支持的方式继续

不是所有应用都支持直接恢复。跨服务继续旧会话也可能失败，尤其是历史中含原服务专用的加密推理内容时。可先新开会话验证当前配置，避免把历史格式问题误判为 Key 失效。

**想把 Codex 官方和第三方会话放在一起？**

1. 打开 **设置 → 通用 → Codex 应用增强 → 统一 Codex 会话历史**
2. 开启时阅读确认框，再决定是否同时迁入已有官方会话；迁入前会自动备份
3. 在会话历史中检查结果，并新开一条会话测试当前配置
4. 关闭时，如果存在迁移备份，可选择恢复当时迁入的会话。需要还原时先读清楚恢复选项，不把关闭开关理解为所有历史都会自动倒回

统一历史不能保证跨服务的加密推理内容可继续使用。新会话正常而旧会话失败时，先检查历史兼容性。

会话可能包含代码、文件路径、附件和个人信息。分享截图或导出前请逐项检查；不要公开整个会话目录来“方便排查”。

### 5.5 MCP：连接工具和数据源

![扩展资源：从当前应用进入 MCP、Skills、Prompts 等工具](images/02-resources.png)

图中 ① MCP 管理工具连接；② Skills 管理技能；③ Prompts 管理常用指令；④ 通用 Agents 入口尚未开放。

1. 先选目标应用，再打开 **扩展资源 → MCP**
2. 添加可信 MCP 服务，或导入自己已有的配置
3. 按服务官方说明填写启动命令/连接地址及需要的参数
4. 选择要同步到的应用并保存
5. 重新启动需要重读配置的目标应用，确认工具能被识别

MCP 可能运行本地程序、读取文件或访问外部服务。先读清楚它需要的权限，不要照抄陌生配置里的执行命令，也不要把认证信息放进公共仓库。Pi 没有同样的原生 MCP 注册入口，本版不会为它伪造一个。

### 5.6 Skills：安装与同步技能

1. 打开 **扩展资源 → Skills**
2. 从可信来源发现或添加技能，先查看内容和来源
3. 安装后选择目标应用，检查同步状态
4. 回到目标应用，按它自己的技能使用方式测试
5. 更新前查看变化；不再需要时从管理页卸载，确认影响范围

Skills 不一定只是说明文字，也可能携带脚本。不要因为来源出现在搜索结果里就默认安全。存储位置、同步方式及应用支持范围以 Skills 管理页为准。

### 5.7 Prompts：保存常用指令

1. 先选择目标应用，打开 **扩展资源 → Prompts**
2. 新建一条，填名称和自己希望重复使用的指令
3. 保存后选择启用；切换前检查是否会写入该应用的指令文件
4. 在目标应用中确认指令已读取

不同应用有不同指令文件和范围。Pi 的系统提示、项目指令和模板也有各自入口；不要把个人密码或项目秘密保存成准备公开分享的模板。

### 5.8 项目切换、工作区和特定应用工具

**项目切换适合反复切换一组配置，不是必须的入门步骤。**

1. 在 **设置 → 通用** 开启 **显示项目切换**
2. 先把当前应用的供应商、MCP、Skills 等调到预期状态，再从顶部项目入口选择 **新建项目**，命名并保存当前快照
3. 以后在项目菜单选择已保存项目，会直接应用相应分组的快照；检查当前供应商和资源是否正确，再开始工作
4. 想撤销切换时，重新应用先前保存的项目。选择 **不使用项目** 只取消项目关联，**不会把实际配置还原到之前的样子**

Claude Code、Claude Desktop、Codex 是三个独立分组，各自保存和应用自己的快照；切换一侧不会替另一侧保存或切换。同一个项目名称不表示所有应用已经各自保存了快照。“本侧未保存”时先检查该侧范围。切换时当前配置会保存回原项目，重要实验前另外保留备份。

其它按应用显示的工具：

- **工作区文件**：从“扩展资源”打开，确认当前应用和目标目录，再编辑对应文件。先理解文件用途，不要把整个个人目录当工作区
- **OpenClaw**：切到 OpenClaw 后，扩展资源提供环境变量、工具权限、Agent 默认设置等专用入口；权限改变前先理解后果
- **Hermes**：切到 Hermes 后，可查看/编辑持久记忆或打开本地控制台。删除记忆会影响之后的行为，先保留需要的内容
- **Agents**：当前通用 Agents 页面仍是“尚未开放”的占位，不能用它创建或管理通用自主代理

这些是按需使用的进阶能力。第一天只完成一次对话即可，不需要把所有入口都打开。

## 6 设置备份升级与排障

### 6.1 语言外观与凭据保护

![通用设置：语言、外观和主页面显示](images/03-settings-general.png)

图中 ① 通用页；② 语言；③ 主页面应用/项目入口；④ 保留 Codex 官方登录；⑤ 统一 Codex 会话历史。

- **语言和主题**：设置 → 通用，可选界面语言及浅色/深色/跟随系统
- **应用入口**：设置 → 通用 → 主页面显示，开启自己实际使用的应用即可
- **凭据保护**：设置 → 认证。默认使用系统凭据库；系统凭据库不可用时，首次启动可能要求设置保护口令
- **保护口令**：由你自行设置并妥善保存，不要截图、提交 Git 或发到聊天中。换电脑恢复时可能需要它，普通服务账号密码不能替代它
- **云同步**：入口是“设置 → 高级 → 云同步”，支持 WebDAV 或 S3 兼容存储；首次跨机迁移按 [6.4](#64-导入导出与配置档的区别) 的顺序操作

**调整首配时的分享选择：** 设置 → 通用 → 窗口行为，分别调整 **使用统计** 与 **站点实测数据共建**。这是两个独立开关；关闭后不再按该开关继续分享，不能把它理解为自动删除接收方已有数据。

若首次启动就显示“系统凭据库不可用”，先检查系统凭据服务/会话状态，或按应用提示自行设置保护口令。不要为了跳过这一页删除凭据文件。

### 6.2 先备份，再做大改动

![高级设置：数据管理、备份与恢复、云同步和诊断](images/05-settings-advanced.png)

图中 ① 高级页；② 数据导入/导出；③ 本机备份与恢复；④ 云同步。

1. 进入 **设置 → 高级 → 备份与恢复**
2. 手动创建一次备份，确认列表中出现新快照
3. **准备导出到另一台电脑时，先到“设置 → 认证 → 凭据保护”自行设置保护口令**。即使系统凭据库正常工作，也需要这一步；没有保护口令时导出会被拒绝
4. 再用 **设置 → 高级 → 数据管理 → 导出 SQL 备份**，保存到自己控制的位置，并记住生成这份备份时的保护口令
5. 确认备份和恢复条件都齐全，再升级、迁移或大范围调整

![备份与恢复：先确认备份列表，再执行恢复](images/09-backup-settings.png)

图中 ① 展开备份与恢复；② 自动备份间隔；③ 保留数量；④ 立即备份。

本机快照、可迁移导出和云同步不是同一件事。备份也不是公开可分享的样例，它可能包含服务配置、账号信息和凭据相关数据。即便有加密，也应限制访问。

恢复时：先备份当前状态，选择正确快照/导出文件。导入加密备份时填写 **创建这份备份时的保护口令**；导入会替换配置，保留本机登录与同步凭据，本机保护口令保持不变。旧版未加密备份不要求该口令。读完覆盖提示后再确认。恢复后检查服务、应用的当前档位和真实请求，而不只看“导入成功”。

### 6.3 从 cc-switch 迁移

1. 先在原工具保留备份，关闭会同时修改同一配置的工具
2. 打开 LoongPort 的 **设置 → 高级**
3. 检测到可导入的 cc-switch 数据时，会出现 **从 cc-switch 导入**；没有该入口不代表需要随意复制数据库
4. 打开导入预览，核对范围和数量，再确认
5. 导入后逐个检查应用、当前供应商和资源，完成一次真实请求

迁移按现有导入能力复制配置，不要求你删除 cc-switch 原数据。源数据版本过新或来源不存在时，入口可能不显示。不要在两个工具里同时来回切换同一应用的配置。

### 6.4 导入导出与配置档的区别

| 名称                   | 主要用途                     | 不应误认为                    |
| ---------------------- | ---------------------------- | ----------------------------- |
| 设置中的导入/导出配置  | 搬迁或恢复应用数据           | 可以安全公开的说明文件        |
| 备份与恢复             | 回到本机历史快照             | 永远兼容任意旧版本            |
| 自动切换旁的顺序配置档 | 保存一组档位优先级           | 包含服务账号与 Key 的完整备份 |
| 项目切换快照           | 在支持范围内切换一组项目资源 | 只改变某一个排序列表          |

收到来源不明的导入文件或深链接时，先核对目标地址、应用和导入内容。导入配置可能改变请求接收方，不应只因为别人说“帮你修好”就直接确认。

#### 第一次把数据迁到另一台电脑

1. 在**有完整数据的旧电脑**先备份，并准备可用于恢复的保护口令
2. 打开 **设置 → 高级 → 云同步**，选择 **WebDAV** 或 **S3 兼容存储**，按自己受信任的存储服务填写连接信息、远程目录/对象路径和同步配置名
3. 点击 **测试连接**，确认连接正常，再 **保存配置**；保存后的连接测试结果也要检查。凭据由你本人填写，不放进截图或公开说明
4. 在旧电脑点 **上传到云端**，核对目标位置和快照信息。**确认上传会覆盖该位置已有的同步数据**
5. 在新电脑设置相同目的地，先 **从云端下载**，核对来源设备、时间和内容，备份本机已有数据后再确认恢复。**下载恢复会替换本机数据与技能配置**
6. 若提示恢复云端保护，输入云端快照的保护口令，按恢复说明继续；这种云端恢复流程与普通配置导入不同，恢复后该设备可能改用云端快照的保护口令
7. 确认服务、资源和真实请求正常后，再决定是否开启 **自动同步**。自动同步会在本地数据库变更后上传，不是自动解决多设备冲突的保证

**不要在新电脑先上传空数据。** 切换 WebDAV/S3 时要检查启用状态，两个同步方式不是同时写入的双备份。云端没有数据或版本不兼容时先停止恢复，核对目标目录与版本，不反复覆盖尝试。

### 6.5 更新与回退

1. 升级前按 6.2 保留备份，保存正在进行的工作
2. 打开 **设置 → 关于**，检查当前版本和更新提示
3. 稳定版用户保持测试版更新关闭；确需 ZCode 等测试功能再考虑测试通道
4. 安装后重新打开，核对版本、当前配置和一次真实请求

Windows 安装版、macOS、Linux AppImage 支持应用内更新流程。Windows Portable、Linux `.deb`/`.rpm` 应按对应发行方式更新，不要套用安装版步骤。

需要回退时：关闭应用，从官方 Releases 选择已知可用的旧版本，并准备与它兼容的备份。**不要让旧程序直接覆盖较新数据库。** 如果出现“数据库版本过新”，按恢复界面或版本说明处理，保留现有数据，不能把删库当作回退步骤。

### 6.6 按现象排障

| 你看到的现象                 | 先做什么                                                          | 不要先做什么                     |
| ---------------------------- | ----------------------------------------------------------------- | -------------------------------- |
| 找不到 Codex/Claude 等入口   | 更多应用，或设置 → 通用 → 主页面显示                              | 重装所有程序                     |
| 提示没有应用配置             | 先安装并运行一次目标应用，检查设置中的目录                        | 删除已有配置目录                 |
| 登录成功但没有档位           | 查服务的分组/套餐/额度，再刷新账号                                | 连续重复注册或创建 Key           |
| 切换后还是旧服务             | 核对所选应用和“当前”，重启目标应用，检查环境变量冲突              | 只刷新 LoongPort 列表            |
| `401` / `403`                | 核对服务地址、Key 的权限/有效性和对应账号                         | 公开粘贴 Key 请求帮助            |
| 模型不存在/不支持            | 按服务商列表核对准确模型 ID 与协议                                | 只把显示名称写成想用的模型       |
| 连接 `127.0.0.1` 失败        | 核对本地路由是否运行、应用是否仍被接管；恢复连接或按 3.6 退出接管 | 随意改端口或结束后台后不恢复配置 |
| 自动切换开着但未生效         | 看是否显示“已暂停”，核对路由、模型兼容和已应用列表                | 把开关亮着当成全部成功           |
| 调完顺序没变化               | 看“更改尚未生效”，点应用更改或取消                                | 反复拖动而不提交                 |
| 用量图表为空                 | 查日期、应用筛选和记录来源，开启路由记录后再测试                  | 认定没有任何消费                 |
| 生图页没有档位               | 查账号是否提供生图分组，刷新服务                                  | 手改聊天模型冒充生图             |
| 历史会话继续失败，新会话正常 | 检查跨供应商历史兼容，保留旧记录                                  | 立即轮换所有 Key                 |
| 更新下载失败                 | 查网络和官方 Releases，按正确安装包手动更新                       | 使用陌生镜像“修复包”             |
| 解锁/导入失败                | 检查保护口令、系统凭据库、版本和文件来源                          | 删除加密文件或公开发数据库       |

**仍然不行时，准备这份最小反馈：**

- LoongPort 版本、操作系统和目标应用版本
- 从哪个入口开始，点了什么，期望看到什么，实际看到什么
- 错误文字和出现时间，是否新会话也能复现
- 已遮去账号、Key、域名、路径和对话内容的截图
- 需要日志时，从诊断入口获取并先检查内容；不要上传整个个人配置目录

公开反馈使用 [官方 Issues](https://github.com/SailingLoong/LoongPort/issues)。涉及安全漏洞或未脱敏数据时，先阅读 [安全政策](../../SECURITY.md)，不要直接公开。

### 6.7 需要时再调的进阶设置

- **自定义配置目录**：设置 → 高级 → 配置文件目录。选中目标应用的真实目录，保存，并按提示重启。只有应用确实使用自定义目录时才改；路径不一致会导致“改了却没生效”
- **全局出站代理**：设置 → 高级 → 全局出站代理。填写可信代理地址，测试连接后保存；清除地址后也要保存。它影响 LoongPort 对外访问，和本机转发 AI 请求的“本地路由”不是同一个开关
- **工具版本与安装诊断**：设置 → 关于，查看目标 CLI 的版本、安装状态和诊断信息；按系统类型核对提示后再安装或升级。不要把客户端安装错误当成服务账号错误
- **诊断与排障**：设置 → 高级可调整日志、连通性检查与请求修正。默认正常时不必改超时、重试或修正规则；反馈问题时先保留最小复现，再按明确原因修改

## 测试版附录 ZCode

**仅适用于 v6.26.3-beta.2；稳定版 v6.26.2 不含此入口。** 不需要 ZCode 的用户可以跳过。

1. 先安装并启动 ZCode，确认它自己的个人配置目录
2. 在测试版 LoongPort 的应用栏添加入口或“设置 → 通用 → 主页面显示”中开启 **ZCode**
3. 进入 ZCode 页，添加个人供应商
4. 填服务地址、API Key 和协议：Anthropic Messages、OpenAI Chat Completions 或 OpenAI Responses
5. 填服务商提供的模型 ID，每行一个，保存
6. 回到 ZCode，选择和测试该供应商/模型

边界：这里只管理个人供应商与模型 ID。账号登录、默认模型、代理、MCP、Skills 和高级模型能力参数仍在 ZCode 管理。其它来源的个人供应商可能只读。

图中 ① ZCode 应用；② 添加个人供应商；③ 已保存的地址、协议和模型；④ 编辑入口。
