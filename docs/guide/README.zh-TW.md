## 1 安裝前要準備什麼

### 1.1 先分清三個東西

- **應用**：你真正與 AI 對話的工具，例如 Codex 或 Claude Code
- **服務與帳號**：提供模型存取的服務及你在該服務的帳號，可以是官方 API 或相容的中轉站
- **檔位**：該帳號下可用的一套存取設定；不同檔位可能有不同模型、價格、倍率和限額

LoongPort 幫你管理這些設定，並在需要時透過本機的本地路由轉發請求。它不是模型，也不替你購買服務；服務商帳號、額度和使用條款仍由對應服務商管理。

**最少需要準備：** 一臺支援的電腦、一個已安裝並執行過的 AI 應用，以及一份你有權使用的服務存取權限。只安裝 LoongPort，不等於已經安裝 Codex 或 Claude Code。

### 1.2 下載正確的安裝套件

從 [LoongPort 官方下載頁](https://loongport.dev/zh/download) 或 [官方 GitHub Releases](https://github.com/SailingLoong/LoongPort/releases) 下載。初次使用優先選穩定版；不要因為測試版的版本號較大就直接選它。

| 你的系統                                    | v6.26.2 對應檔案                            | 選擇建議                                    |
| ------------------------------------------- | ------------------------------------------- | ------------------------------------------- |
| Windows 10 或更高，一般 Intel/AMD 電腦      | `LoongPort-v6.26.2-Windows-Setup.exe`       | 推薦安裝版；按安裝精靈完成                  |
| Windows ARM64 電腦                          | `LoongPort-v6.26.2-Windows-arm64-Setup.exe` | 不要誤選一般 x86_64 套件                      |
| Windows，明確需要免安裝                     | 對應架構的 `Windows-Portable.zip`           | 解壓後執行；更新時下載新壓縮檔              |
| macOS 12 或更高                             | `LoongPort-v6.26.2-macOS.dmg`               | Intel 與 Apple Silicon 通用；拖入「應用程式」 |
| Linux x86_64，Ubuntu 22.04 或相近的新發行版 | `LoongPort-v6.26.2-Linux-x86_64.AppImage`   | 賦予可執行權限後啟動；執行環境需要支援 FUSE |
| Linux，使用發行版套件管理員                   | 對應 `.deb` 或 `.rpm`                       | 由套件管理員安裝；不使用應用內原地更新        |

Linux 桌面版需要 WebKitGTK 4.1 和合適的 glibc。無桌面伺服器、Ubuntu 20.04 等舊系統請看 [LoongPort CLI 指南](../loongport-cli.md)，不要在伺服器上反覆嘗試桌面安裝套件。

macOS 版本目前未經 Apple 簽名與公證。若系統阻止開啟，先核對來源、檔案是否完整及官方發行說明；按 [下載頁](https://loongport.dev/zh/download) 的針對性說明處理。不要關閉整臺電腦的安全保護，也不要執行陌生網站提供的「修復」指令碼。

**這一步完成的標誌：** LoongPort 能開啟視窗，沒有安裝或執行階段程式庫錯誤。首次開啟可能先要求解鎖憑證保護，見 [6.1](#61-語言外觀與憑證保護)。

### 1.3 先初始化要使用的應用

1. 按目標應用程式的官方說明安裝 Codex 或 Claude Code
2. 新開一個終端，執行 `codex --version` 或 `claude --version`，確認能顯示版本
3. 在一個你允許 AI 使用的資料夾中啟動該應用一次，完成它自己的初始化
4. 暫時退出該應用，再開啟 LoongPort

不要把別的工具或公司專案資料夾當成「練習目錄」。第一次測試可使用自己新建的空資料夾。

如果應用不存在或設定目錄尚未初始化，LoongPort 可能提示「尚未找到應用設定，請先啟動應用完成初始化」。這不是讓你重新購買 API，也不是讓你刪除設定檔案。

### 1.4 認識主介面

![應用工作臺：主導覽、應用選擇與檔位列表](images/01-application-workspace.png)

圖中 ① 先選擇要管理的應用；② 新增服務；③ 核對目前檔位；④ 自動故障切換開關；⑤ 滑鼠移到目標行後可點「設為目前檔位」。

- **應用**：決定正在管理哪個應用，檢視目前檔位、切換和安排備用順序
- **服務與帳號**：集中檢視已連線的服務，處理登入、重新整理、餘額和帳號設定
- **生圖**：使用生圖檔位生成圖片，或設定給 CLI 使用的生圖工具
- **使用記錄 / 用量**：分別查工作階段歷史、請求與費用
- **擴充資源**：MCP、Skills、Prompts、統一供應商及特定應用的工作區工具
- **中轉站廣場**：瀏覽可接入的站點，也可輸入自己的服務網址。設定控制推薦列表的顯示，不會移除廣場入口或網址輸入能力
- **設定**：語言、應用顯示、連線、驗證、備份和更新

應用欄沒有你要用的工具時，開啟「更多應用」或應用欄的新增入口；也可到「設定 → 通用 → 主頁面顯示」開啟。顯示一個應用入口不會替你安裝該應用。

## 2 讓第一個應用成功對話

目標：先讓一個應用、一個服務、一個檔位跑通。第二個服務和自動故障切換稍後再加。

### 2.1 選擇接入方式

點選 **新增服務**，根據你已經有什麼選擇一條路：

| 你手裡已有的東西                                    | 選擇                                      |
| --------------------------------------------------- | ----------------------------------------- |
| 中轉站網址和該站帳號                                | **中轉站**，按 2.2 操作                   |
| DeepSeek、智譜 BigModel 或 opencode 的官方 API 帳號 | **官方 API**，按 2.3 操作                 |
| 服務商給出的 API 位址、API Key、模型 ID             | **手動新增**，按 2.4 操作                 |
| 已在 cc-switch 配好，想遷移                         | 先備份，再看 [6.3](#63-從-cc-switch-遷移) |

![新增服務：中轉站、官方 API、手動新增三種入口](images/06-add-service.png)

圖中 ① 按現有帳號/Key 選擇接入方式；② 輸入服務網址；③ 開啟該服務的註冊或登入頁面。

### 2.2 用中轉站帳號接入

**先準備：** 可信服務商的網址、你在該站的帳號，以及至少一個有額度且允許使用的檔位。

1. 首次設定精靈名為 **連接你的第一個服務**。在「中轉站網址」中填該服務的位址。示範寫作 `https://example.com`，實際請用自己的服務位址
2. 點選 **進入註冊 / 登入**
3. 確認開啟的頁面網域確實屬於所選服務。已有帳號就登入，沒有帳號再按該服務的規則註冊
4. 登入完成後，回到 LoongPort 的 **確認應用設定** 頁面
5. 為這次要用的應用選擇一個可用設定，其他應用先保留 **暫不設定**
6. 檢視「分享服務使用與實測資料，幫助完善適配並查看社群實測」及「瞭解分享內容」。這是選填項目，不勾選也能使用；按自己的意願選擇
7. 點選 **完成設定**

![首次連線：填寫自己的服務網址](images/10-first-service.png)

圖中 ① 服務網址，實際要替換 example.com；② 官方 API / 廣場可選入口；③ 進入所選站點。

![確認應用設定：選目標應用程式、檔位和可選的資料分享項目](images/11-confirm-application.png)

圖中 ① 不使用的應用保留「暫不設定」；② 為目標應用程式選檔位；③ 閱讀可選資料分享並自行選擇；④ 完成設定。

LoongPort 會根據服務提供的資訊取得可用檔位，並按支援的設定格式寫入你選擇的應用。某些服務會涉及建立或重複使用 API Key；操作對象始終是你選定的服務帳號。

**成功的標誌：** 「服務與帳號」裡出現該帳號，「應用」頁能看到檔位和目前設定。然後一定繼續完成 [2.5 的真實對話測試](#25-驗證真的能用)。

**如果沒有成功：**

- 關閉了登入視窗：重新點選進入註冊 / 登入即可，不要重複註冊帳號
- 帳號已儲存但沒有可用設定：檢查該服務的額度、訂閱、分組權限和模型支援，再重新整理帳號
- 提示站點不相容：確認是否為受支援的 sub2api / new-api 服務；已有 API Key 時可檢查「手動新增」是否適合，不能保證任意網站都能自動登入
- 已登入卻仍顯示登入過期：從「服務與帳號」對該帳號重新登入；不要把密碼、Cookie 或登入回應發到公開 Issue

### 2.3 用官方 API 帳號接入

1. 點選 **新增服務 → 官方 API**
2. 選擇頁面實際列出的廠商：DeepSeek、智譜 BigModel 或 opencode
3. 在該廠商的真實頁面完成登入
4. 回到 **確認應用設定**，為目標應用程式選設定，再點 **完成設定**
5. 按 [2.5](#25-驗證真的能用) 測試

「官方 API」指廠商 API 服務，不等於 ChatGPT、Claude 等聊天產品的訂閱。API 計費、套餐和可用模型以該帳號實際權限為準。opencode 帳號可能顯示不同套餐設定，請選擇自己有權使用的那一項。

### 2.4 只有 API Key：手動新增

**先準備這四項，缺一項先向服務商確認：**

| 欄位     | 示範值                        | 實際應填什麼                                          |
| -------- | ----------------------------- | ----------------------------------------------------- |
| 名稱     | `示範服務`                    | 自己能認出的名稱                                      |
| API 位址 | `https://api.example.com/v1`  | 服務商給目標應用程式的完整 Base URL；不要憑經驗亂加 `/v1` |
| API Key  | `REPLACE_WITH_YOUR_API_KEY`   | 該服務生成的金鑰；不把範例文字原樣儲存                |
| 模型 ID  | `MODEL_ID_FROM_YOUR_PROVIDER` | 服務商模型清單裡確切的 ID；顯示名稱未必等於 ID        |

1. 先在應用欄選擇要設定的應用，例如 **Codex**
2. 點選 **新增服務 → 手動新增**
3. 首次出現「關於通用設定」說明時，閱讀後點 **我了解了**。有對應預設就選預設，否則選 **自訂設定**
4. 填名稱、API 位址、API Key 和模型資訊；不同應用的表單不完全相同
5. 檢查服務支援的 API 協定。OpenAI Responses、Chat Completions、Anthropic Messages 不能只看名字相近就混用
6. 儲存後返回「應用」，在新增檔位上點 **設為目前檔位**
7. 按下一節重新啟動目標應用程式並測試

![手動新增供應商：先選擇目標應用程式，再填寫該應用所需資訊](images/07-manual-provider.png)

圖中 ① Key 由你本人填入，不用截圖中的佔位提示；② 核對 API 請求位址；③ 改成服務確實支援的模型；④ 上游格式要與服務介面匹配。圖中未填寫金鑰，也沒有儲存或呼叫服務。

**不要做：** 不要把教學中的 JSON 整份覆蓋到已有設定檔；不要在公開聊天、截圖或 Git 中貼上真實 Key。表單裡有「設定內容」並不表示初次使用者必須手寫 JSON；優先使用現有表單和預設。

### 2.5 驗證真的能用

1. 回到 **應用**，確認應用名稱正確，預期檔位標著 **目前**
2. 退出並重新啟動目標 CLI。Codex 相關設定也可能影響共用設定的桌面應用；若彈出退出/重啟確認，先儲存正在進行的工作，再按提示選擇
3. 在目標應用程式傳送一句不含任何私人資料的話，例如：`請用一句話介紹你能做什麼`
4. 看到正常回覆後，再開始自己的任務
5. 開啟本地路由時，還可在「用量」檢視相應請求記錄；這用於進一步核對，不代替實際回覆

**以下都不能單獨證明成功：** 登入成功、出現「已儲存」、檔位有「目前」標記、餘額不為零。它們分別證明不同階段完成，真正可用仍要看目標應用程式能否發出並完成請求。

出現 `401/403`、模型不存在或連線失敗，直接看 [6.6 排障表](#66-按現象排障)。不要為了排障連著建立許多新 Key。

## 3 讓故障時自動換到備用檔位

### 3.1 先確認本版支援什麼

**v6.26.2 的介面名稱是「自動故障切換」。** 你先確定允許嘗試的檔位和優先級，目前請求失敗時，系統按已套用列表嘗試其他可用檔位。

本版沒有舊教學中的 **「省心 / 自主」切換**，也不提供 **「價格最低 / 回應最快」自動擇優策略**。這些舊宣傳不能等同於現在的自動故障切換。你仍可參考表格的倍率、錯誤率、首字耗時等指標，自己安排順序。

適用於本地路由完整支援的 **Claude Code、Codex、Gemini、Grok Build**。原生登入、某些官方帳號或不支援此路由方式的設定不參加自動切換，介面會顯示原因。不要把「能新增此應用」理解為「此應用支援所有功能」。

### 3.2 開啟一次

**前置條件：** 第 2 章已經跑通；目標 CLI 已初始化；同一模型至少有兩個你願意使用的相容檔位。只有一個檔位時，開關不會憑空生成備用服務。

1. 開啟 **應用**，選擇目標應用程式
2. 在「可用檔位」旁開啟 **自動故障切換**
3. 如提示初始化、連線或設定問題，先處理提示。開啟成功需要本地路由執行並接管這個應用的連線
4. 檢查列表的優先級、目前檔位以及不參與切換的原因
5. 在目標應用程式再發一條測試訊息，確認開啟後仍能正常對話

![應用工作臺：自動故障切換、檔位指標與優先級](images/01-application-workspace.png)

圖中 ① 先選擇要管理的應用；② 新增服務；③ 核對目前檔位；④ 自動故障切換開關；⑤ 滑鼠移到目標行後可點「設為目前檔位」。

**成功的標誌：** 開關保持開啟，沒有「自動故障切換已暫停」的提示，目標應用程式的請求仍正常。需要核對連線時，開啟 **設定 → 連線設定 → 本地路由**，檢視執行狀態和對應應用是否已啟用路由。

### 3.3 設定備用順序，記得點「套用變更」

1. 開啟自動故障切換後，點 **查看全部檔位**，找到希望加入的設定
2. 需要固定模型時，用 **檔位模型** 選擇該模型；也可按帳號篩選或搜尋
3. 拖動順序，或點選指標列排序。**數字越小越先嘗試**；顯示「—」的檔位不參與自動切換
4. 出現 **變更尚未生效** 時，逐項核對目前可見列表
5. 點選 **套用變更**；不想改變實際設定就點 **取消**
6. 確認未生效提示消失，再做一次真實請求

![調整後出現待生效提示：檢查列表，再套用或取消](images/08-pending-changes.png)

圖中 ① 目前篩選條件；② 更改仍是草稿；③ 放棄本次調整；④ 核對後套用。

**這裡特別容易誤會：** 開啟自動故障切換後，篩選、排序和選擇模型可以構成待套用的調整；不是「查看表格」就已經改變執行中的列表。點「套用變更」時還可能套用所選模型，並在需要時選擇支援它的檔位。提交前請檢查模型、帳號和列表範圍。

列裡的「—」表示沒有資料或不適用，不代表價格為零、從不失敗或餘額無限。表格中的餘額可能是同一個帳號共享的餘額，不能把多筆餘額直接相加。

### 3.4 儲存常用順序

「可用檔位」旁的 **配置檔** 儲存的是檔位順序，不是整個應用程式的備份。

1. 調整到想要的列表
2. 開啟配置檔選單，點 **保存目前順序…**，輸入如「日常使用」的名稱
3. 之後選擇已儲存的配置檔，檢查待套用列表
4. 按介面提示點 **套用變更**

同名儲存會覆蓋該順序配置檔。匯入/匯出順序配置檔適合遷移排序；它不會替對方建立服務帳號、金鑰或可用額度。沒有相同檔位時不能期待完整復原。

### 3.5 故障時看哪裡

- **暫時略過：等待連線恢復**：先看最近錯誤、服務額度和網路狀態，不要連續點選重試
- **已略過：不支援目前選擇的模型**：換成該檔位確實支援的模型，或選擇另一檔
- **已屏蔽**：這是你排除的檔位；確定要重新使用時才取消屏蔽
- **目前使用官方登入，不進行自動故障切換**：保留官方登入使用方式，或明確選擇支援路由的 API 設定
- **自動故障切換已暫停**：點 **恢復連線**，再核對連線設定；不要把亮著的開關當成請求一定已走路由

「清除錯誤記錄」不代表上游問題已經修復，也不是更換金鑰的替代操作。優先保留錯誤訊息，定位原因後再清理。

### 3.6 關閉自動切換，或完全恢復直連

這三種動作影響不同：

| 你想做什麼               | 操作                                                    | 結果                                                 |
| ------------------------ | ------------------------------------------------------- | ---------------------------------------------------- |
| 不再故障時換檔位         | 在應用頁關閉 **自動故障切換**                           | 停止自動換檔；本地路由和應用接管不一定關閉           |
| 僅讓一個應用退出本地路由 | **設定 → 連線設定 → 本地路由 → 路由啟用**，關閉對應應用 | 恢復該應用的直接設定；其他應用可繼續路由             |
| 停止整個本地路由         | 同一位置關閉 **路由總開關**                             | 停止服務，並恢復已接管的設定；會影響所有依賴它的應用 |

![連線設定：路由總開關與按應用的路由開關](images/04-connection-settings.png)

圖中 ① 連線設定；② 全部應用共用的路由總開關；③ 按應用啟停路由；④ 本機服務位址與埠。

恢復後重新啟動目標應用程式並測試。不要在路由仍接管時直接退出後臺、刪除設定或手工改埠，否則目標應用程式可能繼續指向一個已經停止的本機位址。

## 4 日常切換模型與管理服務

### 4.1 手動換一個檔位

1. **應用**中選擇目標應用程式
2. 找到目標檔位，檢視服務、帳號和模型是否正確
3. 點選 **設為目前檔位**
4. 如出現退出/重啟確認，先處理正在進行的工作，再選擇相應操作
5. 重新啟動目標應用程式，傳送測試訊息

選擇新檔位可能把之後的請求傳送給另一家服務商。對話、程式碼或附件是否允許交給該服務，應由你先確認。

### 4.2 改模型：先確認服務真的支援

1. 在 **檔位模型** 篩選框中選擇需要的模型；總共只有一個模型時，這個篩選框不會出現
2. 只使用明確支援該模型的檔位；模型名稱不熟悉時先檢視服務商的模型清單
3. **自動故障切換關閉時**：篩選只是檢視。還要在目標檔位行點選 **設為目前檔位**，才能提交該檔位和所選模型
4. **自動故障切換開啟時**：檢查待生效的模型與檔位列表，再點 **套用變更**。不要把篩選結果當成已生效設定
5. 在目標應用程式確認生效模型，再傳送簡短測試

搜尋框是查詢工具，不是購買權限，也不會讓不支援的模型變得可用。模型目錄可能滯後；伺服器回傳「模型不存在」時，應以服務商實際支援範圍為準。

### 4.3 連線測試與模型驗證不是一回事

- **連通性/速度測試**：幫助判斷請求能否完成、耗時如何；測試本身可能產生費用
- **模型驗證**：在支援的託管檔位上，透過有限證據幫助檢查模型行為是否與宣稱的模型相符；不是官方認證，也不是絕對鑑定

做模型驗證時：

1. 在支援的檔位操作區開啟 **模型驗證**
2. 選擇該檔位提供的模型
3. 閱讀提示後開始驗證，等待結果；不要重複提交同一任務
4. 檢視結論和證據，有疑問時向服務商核對；需要停止時使用取消入口

沒有異常標記不等於已經驗證通過。「暫無資料」也不等於服務品質差。不要僅憑一次驗證報告作確定性指責。

### 4.4 帳號過期、重新整理、儲值與對帳

1. 點選 **服務與帳號**，選擇需要處理的服務帳號
2. 登入過期時重新登入；登入有效但檔位變了時重新整理帳號
3. 需要額度時，使用該帳號提供的儲值入口，核對開啟頁面的網域、金額和套餐
4. 需要核對花費時，先檢查本機「用量」，再看該站的用量/帳單或 **扣費對帳**

登入狀態過期和 API Key 失效是兩件事。有的帳號過期後已有 Key 仍可請求，所以不要一見登入過期就刪除全部設定。

本地估算費用與服務商實際扣費可能採用不同價表或時間範圍。對帳時統一時間視窗，並考慮儲值、其他裝置呼叫、套餐、倍率、快取和計價差異；不能只看一個比值就斷定多扣費。

### 4.5 管理自訂設定、統一供應商與官方登入

- **編輯/複製自訂設定**：在應用頁展開 **設定管理**，找到對應項。服務帳號生成的託管設定應到「服務與帳號」的帳號詳情處理，避免重新整理後誤以為設定被「丟失」
- **統一供應商**：到 **擴充資源 → 統一供應商**，維護可供多個應用使用的供應商設定；逐個檢查目標應用程式、協定和模型，不把一個應用的格式照搬到全部應用
- **切換已有官方設定**：在相應應用選擇已有的官方設定，並按提示重新啟動。Codex 的官方憑證保護開關在「設定 → 通用」。這與下文「還原官方登入」的重置動作不同
- **桌面應用**：Claude Desktop 的設定形狀與 Claude Code 不同。先選正確應用，再使用其直連/模型映射表單；需要對映時依賴本地路由，不能把 CLI 的操作全部照搬

OpenCode、OpenClaw、Hermes、Pi 採用各自原生設定方式，可能允許多個供應商同時存在；「啟用」不一定等於全域只能選一個。最終模型選擇以該應用自己的介面為準。

### 4.6 管理訂閱授權帳號（OAuth 驗證中心）

**設定 → 驗證 → OAuth 驗證中心** 提供 GitHub Copilot、ChatGPT（Codex OAuth）和 xAI（Grok OAuth）三個帳號區。該能力在介面中標為 **Beta**，與「官方 API」帳號不是一回事，也不保證任意訂閱都能用於任意應用。

1. 先確認自己的訂閱、用途和目標應用程式符合相應平臺條款，再進入對應帳號區
2. 點選登入/新增帳號，在平臺自己的授權頁面完成操作。不要在第三方頁面輸入平臺密碼
3. 回到 LoongPort，確認顯示的是正確帳號；有多個帳號時按需設定預設帳號
4. 在支援該授權方式的供應商表單中選擇對應帳號。設定預設帳號並不等於已切換目標應用程式的供應商
5. 標記「需要重新登入」時使用該帳號的重新登入入口；不再使用時從列表移除前先檢查哪些設定依賴它

成功標誌是授權帳號已被識別，目標設定正確連結，並完成一次實際請求。帳號列表中出現一行不能單獨證明所有呼叫都可用。不要分享授權回應、Cookie、權杖或恢復碼。

### 4.7 需要重新回到 ChatGPT 原生登入

僅在你明確需要移除 LoongPort 的 Codex 路由並重新建立官方登入時使用此操作。一般換檔位不需要先做它。

1. 儲存 ChatGPT 中正在進行的工作
2. 開啟 **設定 → 驗證 → ChatGPT（Codex OAuth）**
3. 點選 **還原官方登入**，閱讀確認內容：應用會退出 ChatGPT、移除 LoongPort 路由，並在備份後刪除目前 Codex 登入狀態
4. 確認後重新開啟 ChatGPT，**重新登入官方帳號**，再做一次測試

**Windows 特別注意：** 此操作需要強制關閉 ChatGPT，不會出現儲存提醒。備份登入狀態不等於以後自動幫你登入；請確保自己可以完成官方登入。

## 5 生圖記錄用量與擴充資源

### 5.1 在 LoongPort 裡生圖

**先準備：** 服務帳號有可用的生圖分組及額度。一般聊天檔位不一定支援圖片生成。

1. 新增或重新整理該服務帳號，讓生圖檔位出現在 **生圖** 頁
2. 開啟 **生圖**；需要管理檔位時選 **連線設定檔**，啟用想用的檔位
3. 返回 **生成**，檢查 **目前連線設定檔**
4. 寫圖片描述，選擇支援的尺寸、品質和張數。第一次先生成 **1 張**
5. 點選 **生成**，等待結果出現在 **生成記錄**
6. 用 **在資料夾中顯示** 找到實際檔案

張數會影響費用，並行提交可能同時發出多次請求。請求較慢時先等待，不要反覆點生成。如果只成功一部分，先保留已成功的圖片，再處理失敗部分。

頁面沒有連線設定檔時，檢查服務是否真的提供生圖分組；不要把聊天模型的名稱手改成圖片模型以為就能使用。

### 5.2 在 CLI 對話中呼叫生圖工具

1. 先按上一節選好生圖連線設定檔
2. 在「生圖」頁檢查 **在 Codex / Claude 對話中提供生圖工具**。本版預設開啟；若已關閉且你需要它，再手動開啟
3. 本版工具註冊目標是 **Codex、Claude Code、Gemini CLI**。首次寫入或重新開啟後，重啟你實際使用的這些 CLI，讓它們重新讀取工具設定
4. 在對話裡明確請求使用生圖工具，並核對 CLI 展示的工具確認與結果

生圖設定與聊天檔位各自獨立，不必為了生圖把正常聊天檔位換掉。CLI 是否呼叫工具、具體權限提示以及輸出位置，以目前 CLI 與頁面顯示為準。

### 5.3 查用量和請求錯誤

1. 點選左側 **用量**
2. 先選日期範圍，再按應用、供應商或模型縮小範圍
3. 檢視請求數、Token、費用和趨勢，再開啟相關請求記錄看錯誤
4. 需要對帳時記錄時間、目標應用程式和模型；向服務商傳送資訊前，先去掉金鑰、帳號和對話內容

沒有記錄時先檢查採集來源、日期範圍和本地路由的「記錄請求用量」設定。透過別的裝置、未被記錄的路徑或不支援的應用發出的請求，不一定出現在這裡。不要把空圖表理解為「絕對沒有消費」。

### 5.4 找回和繼續一次會話

1. 點選 **使用記錄 → 工作階段歷史**
2. 選擇相應應用，按標題或內容搜尋
3. 選中會話，先預覽確認是自己要找的內容
4. 介面提供繼續會話或恢復命令時，按該應用支援的方式繼續

不是所有應用都支援直接恢復。跨服務繼續舊會話也可能失敗，尤其是歷史中含原服務專用的加密推理內容時。可先新開會話驗證目前設定，避免把歷史格式問題誤判為 Key 失效。

**想把 Codex 官方和第三方會話放在一起？**

1. 開啟 **設定 → 通用 → Codex 應用增強 → 統一 Codex 會話歷史**
2. 開啟時閱讀確認框，再決定是否同時遷入已有官方會話；遷入前會自動備份
3. 在工作階段歷史中檢查結果，並新開一條會話測試目前設定
4. 關閉時，如果存在遷移備份，可選擇恢復當時遷入的會話。需要還原時先讀清楚恢復選項，不把關閉開關理解為所有歷史都會自動倒回

統一歷史不能保證跨服務的加密推理內容可繼續使用。新會話正常而舊會話失敗時，先檢查歷史相容性。

會話可能包含程式碼、檔案路徑、附件和個人資訊。分享截圖或匯出前請逐項檢查；不要公開整個會話目錄來「方便排查」。

### 5.5 MCP：連線工具和資料來源

![擴充資源：從目前應用進入 MCP、Skills、Prompts 等工具](images/02-resources.png)

圖中 ① MCP 管理工具連線；② Skills 管理技能；③ Prompts 管理常用指令；④ 通用 Agents 入口尚未開放。

1. 先選目標應用程式，再開啟 **擴充資源 → MCP**
2. 新增可信 MCP 服務，或匯入自己已有的設定
3. 按服務官方說明填寫啟動命令/連線位址及需要的參數
4. 選擇要同步到的應用並儲存
5. 重新啟動需要重讀設定的目標應用程式，確認工具能被識別

MCP 可能執行本機程式、讀取檔案或存取外部服務。先讀清楚它需要的權限，不要照抄陌生設定裡的執行命令，也不要把認證資訊放進公開儲存庫。Pi 沒有同樣的原生 MCP 註冊入口，本版不會為它偽造一個。

### 5.6 Skills：安裝與同步技能

1. 開啟 **擴充資源 → Skills**
2. 從可信來源發現或新增技能，先檢視內容和來源
3. 安裝後選擇目標應用程式，檢查同步狀態
4. 回到目標應用程式，按它自己的技能使用方式測試
5. 更新前檢視變化；不再需要時從管理頁解除安裝，確認影響範圍

Skills 不一定只是說明文字，也可能攜帶指令碼。不要因為來源出現在搜尋結果裡就預設安全。儲存位置、同步方式及應用支援範圍以 Skills 管理頁為準。

### 5.7 Prompts：儲存常用指令

1. 先選擇目標應用程式，開啟 **擴充資源 → Prompts**
2. 新建一條，填名稱和自己希望重複使用的指令
3. 儲存後選擇啟用；切換前檢查是否會寫入該應用的指令檔案
4. 在目標應用程式中確認指令已讀取

不同應用有不同指令檔案和範圍。Pi 的系統提示、專案指令和模板也有各自入口；不要把個人密碼或專案秘密儲存成準備公開分享的模板。

### 5.8 專案切換、工作區和特定應用工具

**專案切換適合反覆切換一組設定，不是必須的入門步驟。**

1. 在 **設定 → 通用** 開啟 **顯示專案切換**
2. 先把目前應用的供應商、MCP、Skills 等調到預期狀態，再從頂部專案入口選擇 **新建專案**，命名並儲存目前快照
3. 以後在專案選單選擇已儲存專案，會直接套用相應分組的快照；檢查目前供應商和資源是否正確，再開始工作
4. 想撤銷切換時，重新套用先前儲存的專案。選擇 **不使用專案** 只取消專案關聯，**不會把實際設定還原到之前的樣子**

Claude Code、Claude Desktop、Codex 是三個獨立分組，各自儲存和套用自己的快照；切換一側不會替另一側儲存或切換。同一個專案名稱不表示所有應用已經各自儲存了快照。「本側未儲存」時先檢查該側範圍。切換時目前設定會儲存回原專案，重要實驗前另外保留備份。

其他按應用顯示的工具：

- **工作區檔案**：從「擴充資源」開啟，確認目前應用和目標目錄，再編輯對應檔案。先理解檔案用途，不要把整個個人目錄當工作區
- **OpenClaw**：切到 OpenClaw 後，擴充資源提供環境變數、工具權限、Agent 預設設定等專用入口；權限改變前先理解後果
- **Hermes**：切到 Hermes 後，可檢視/編輯持久記憶或開啟本地控制檯。刪除記憶會影響之後的行為，先保留需要的內容
- **Agents**：目前通用 Agents 頁面仍是「尚未開放」的佔位，不能用它建立或管理通用自主代理

這些是按需使用的進階能力。第一天只完成一次對話即可，不需要把所有入口都開啟。

## 6 設定備份升級與排障

### 6.1 語言外觀與憑證保護

![通用設定：語言、外觀和主頁面顯示](images/03-settings-general.png)

圖中 ① 通用頁；② 介面語言；③ 主頁面應用/專案入口；④ 非接管切換時保留官方登入；⑤ 統一 Codex 會話歷史。

- **語言和主題**：設定 → 通用，可選介面語言及淺色/深色/跟隨系統
- **應用入口**：設定 → 通用 → 主頁面顯示，開啟自己實際使用的應用即可
- **憑證保護**：設定 → 驗證。預設使用系統憑證庫；系統憑證庫不可用時，首次啟動可能要求設定保護密碼
- **保護密碼**：由你自行設定並妥善儲存，不要截圖、提交 Git 或發到聊天中。換電腦恢復時可能需要它，一般服務帳號密碼不能替代它
- **雲端同步**：入口是「設定 → 進階 → 雲端同步」，支援 WebDAV 或 S3 相容儲存；首次跨機遷移按 [6.4](#64-匯入匯出與配置檔的區別) 的順序操作

**調整首配時的分享選擇：** 設定 → 通用 → 視窗行為，分別調整 **使用統計** 與 **站點實測資料共建**。這是兩個獨立開關；關閉後不再按該開關繼續分享，不能把它理解為自動刪除接收方已有資料。

若首次啟動就顯示「系統憑證庫不可用」，先檢查系統憑證服務/會話狀態，或按應用提示自行設定保護密碼。不要為了跳過這一頁刪除憑證檔案。

### 6.2 先備份，再做大改動

![進階設定：資料管理、備份與還原、雲端同步和診斷](images/05-settings-advanced.png)

圖中 ① 進階頁；② 資料匯入/匯出；③ 本機備份與還原；④ 雲端同步。

1. 進入 **設定 → 進階 → 備份與還原**
2. 點選 **立即備份**，確認列表中出現新快照
3. **準備匯出到另一臺電腦時，先到「設定 → 驗證 → 憑證保護」自行設定保護密碼**。即使系統憑證庫正常工作，也需要這一步；沒有保護密碼時匯出會被拒絕
4. 再用 **設定 → 進階 → 資料管理 → 匯出 SQL 備份**，儲存到自己控制的位置，並記住生成這份備份時的保護密碼
5. 確認備份和恢復條件都齊全，再升級、遷移或大範圍調整

![備份與還原：先確認備份列表，再執行恢復](images/09-backup-settings.png)

圖中 ① 展開備份與還原；② 自動備份間隔；③ 保留數量；④ 立即備份。

本機快照、可遷移匯出和雲端同步不是同一件事。備份也不是公開可分享的樣例，它可能包含服務設定、帳號資訊和憑證相關資料。即便有加密，也應限制存取。

恢復時：先備份目前狀態，選擇正確快照/匯出檔案。匯入加密備份時填寫 **建立這份備份時的保護密碼**；匯入會替換設定，保留本機登入與同步憑證，本機保護密碼保持不變。舊版未加密備份不要求該密碼。讀完覆蓋提示後再確認。恢復後檢查服務、應用的目前檔位和真實請求，而不只看「匯入成功」。

### 6.3 從 cc-switch 遷移

1. 先在原工具保留備份，關閉會同時修改同一設定的工具
2. 開啟 LoongPort 的 **設定 → 進階**
3. 檢測到可匯入的 cc-switch 資料時，會出現 **從 cc-switch 匯入**；沒有該入口不代表需要隨意複製資料庫
4. 開啟匯入預覽，核對範圍和數量，再確認
5. 匯入後逐個檢查應用、目前供應商和資源，完成一次真實請求

遷移按現有匯入能力複製設定，不要求你刪除 cc-switch 原資料。源資料版本過新或來源不存在時，入口可能不顯示。不要在兩個工具裡同時來回切換同一應用的設定。

### 6.4 匯入匯出與配置檔的區別

| 名稱                   | 主要用途                     | 不應誤認為                    |
| ---------------------- | ---------------------------- | ----------------------------- |
| 設定中的匯入/匯出設定  | 搬遷或恢復應用資料           | 可以安全公開的說明檔案        |
| 備份與還原             | 回到本機歷史快照             | 永遠相容任意舊版本            |
| 自動切換旁的順序配置檔 | 儲存一組檔位優先級           | 包含服務帳號與 Key 的完整備份 |
| 專案切換快照           | 在支援範圍內切換一組專案資源 | 只改變某一個排序列表          |

收到來源不明的匯入檔案或深連結時，先核對目標位址、應用和匯入內容。匯入設定可能改變請求接收方，不應只因為別人說「幫你修好」就直接確認。

#### 第一次把資料遷到另一臺電腦

1. 在**有完整資料的舊電腦**先備份，並準備可用於恢復的保護密碼
2. 開啟 **設定 → 進階 → 雲端同步**，選擇 **WebDAV** 或 **S3 相容儲存**，按自己受信任的儲存服務填寫連線資訊、遠端目錄/物件路徑和同步設定名
3. 點選 **測試連線**，確認連線正常，再 **儲存設定**；儲存後的連線測試結果也要檢查。憑證由你本人填寫，不放進截圖或公開說明
4. 在舊電腦點 **上傳至雲端**，核對目標位置和快照資訊。**確認上傳會覆蓋該位置已有的同步資料**
5. 在新電腦設定相同目的地，先 **從雲端下載**，核對來源裝置、時間和內容，備份本機已有資料後再確認還原。**下載恢復會替換本機資料與技能設定**
6. 若提示恢復雲端保護，輸入雲端快照的保護密碼，按恢復說明繼續；這種雲端恢復流程與一般設定匯入不同，恢復後該裝置可能改用雲端快照的保護密碼
7. 確認服務、資源和真實請求正常後，再決定是否開啟 **自動同步**。自動同步會在本機資料庫變更後上傳，不是自動解決多裝置衝突的保證

**不要在新電腦先上傳空資料。** 切換 WebDAV/S3 時要檢查啟用狀態，兩個同步方式不是同時寫入的雙備份。雲端沒有資料或版本不相容時先停止恢復，核對目標目錄與版本，不反覆覆蓋嘗試。

### 6.5 更新與回退

1. 升級前按 6.2 保留備份，儲存正在進行的工作
2. 開啟 **設定 → 關於**，檢查目前版本和更新提示
3. 穩定版使用者保持測試版更新關閉；確需 ZCode 等測試功能再考慮測試通道
4. 安裝後重新開啟，核對版本、目前設定和一次真實請求

Windows 安裝版、macOS、Linux AppImage 支援應用內更新流程。Windows Portable、Linux `.deb`/`.rpm` 應按對應發行方式更新，不要套用安裝版步驟。

需要回退時：關閉應用，從官方 Releases 選擇已知可用的舊版本，並準備與它相容的備份。**不要讓舊程式直接覆蓋較新資料庫。** 如果出現「資料庫版本過新」，按恢復介面或版本說明處理，保留現有資料，不能把刪庫當作回退步驟。

### 6.6 按現象排障

| 你看到的現象                 | 先做什麼                                                          | 不要先做什麼                     |
| ---------------------------- | ----------------------------------------------------------------- | -------------------------------- |
| 找不到 Codex/Claude 等入口   | 更多應用，或設定 → 通用 → 主頁面顯示                              | 重灌所有程式                     |
| 提示沒有應用設定             | 先安裝並執行一次目標應用程式，檢查設定中的目錄                        | 刪除已有設定目錄                 |
| 登入成功但沒有檔位           | 查服務的分組/套餐/額度，再重新整理帳號                                | 連續重複註冊或建立 Key           |
| 切換後還是舊服務             | 核對所選應用和「目前」，重啟目標應用程式，檢查環境變數衝突              | 只重新整理 LoongPort 列表            |
| `401` / `403`                | 核對服務位址、Key 的權限/有效性和對應帳號                         | 公開貼上 Key 請求幫助            |
| 模型不存在/不支援            | 按服務商列表核對準確模型 ID 與協定                                | 只把顯示名稱寫成想用的模型       |
| 連線 `127.0.0.1` 失敗        | 核對本地路由是否執行、應用是否仍被接管；恢復連線或按 3.6 退出接管 | 隨意改埠或結束後臺後不還原設定 |
| 自動切換開著但未生效         | 看是否顯示「已暫停」，核對路由、模型相容和已套用列表                | 把開關亮著當成全部成功           |
| 調完順序沒變化               | 看「變更尚未生效」，點套用變更或取消                                | 反覆拖動而不提交                 |
| 用量圖表為空                 | 查日期、應用篩選和記錄來源，開啟路由記錄後再測試                  | 認定沒有任何消費                 |
| 生圖頁沒有檔位               | 查帳號是否提供生圖分組，重新整理服務                                  | 手改聊天模型冒充生圖             |
| 歷史會話繼續失敗，新會話正常 | 檢查跨供應商歷史相容，保留舊記錄                                  | 立即輪換所有 Key                 |
| 更新下載失敗                 | 查網路和官方 Releases，按正確安裝套件手動更新                       | 使用陌生鏡像「修復包」             |
| 解鎖/匯入失敗                | 檢查保護密碼、系統憑證庫、版本和檔案來源                          | 刪除加密檔案或公開發資料庫       |

**仍然不行時，準備這份最小回饋：**

- LoongPort 版本、作業系統和目標應用程式版本
- 從哪個入口開始，點了什麼，期望看到什麼，實際看到什麼
- 錯誤文字和出現時間，是否新會話也能重現
- 已遮去帳號、Key、網域、路徑和對話內容的截圖
- 需要日誌時，從診斷入口取得並先檢查內容；不要上傳整個個人設定目錄

公開回饋使用 [官方 Issues](https://github.com/SailingLoong/LoongPort/issues)。涉及安全漏洞或未去識別化資料時，先閱讀 [安全政策](../../SECURITY.md)，不要直接公開。

### 6.7 需要時再調的進階設定

- **自訂設定目錄**：設定 → 進階 → 設定檔目錄。選中目標應用程式的真實目錄，儲存，並按提示重啟。只有應用確實使用自訂目錄時才改；路徑不一致會導致「改了卻沒生效」
- **全域出站代理伺服器**：設定 → 進階 → 全域出站代理伺服器。填寫可信代理位址，測試連線後儲存；清除位址後也要儲存。它影響 LoongPort 對外存取，和本機轉發 AI 請求的「本地路由」不是同一個開關
- **工具版本與安裝診斷**：設定 → 關於，檢視目標 CLI 的版本、安裝狀態和診斷資訊；按作業系統類型核對提示後再安裝或升級。不要把客戶端安裝錯誤當成服務帳號錯誤
- **診斷與排障**：設定 → 進階可調整日誌、連通性檢查與請求修正。預設正常時不必改超時、重試或修正規則；回報問題時先保留最小重現，再按明確原因修改

## 測試版附錄 ZCode

**僅適用於 v6.26.3-beta.2；穩定版 v6.26.2 不含此入口。** 不需要 ZCode 的使用者可以跳過。

1. 先安裝並啟動 ZCode，確認它自己的個人設定目錄
2. 在測試版 LoongPort 的應用欄新增入口或「設定 → 通用 → 主頁面顯示」中開啟 **ZCode**
3. 進入 ZCode 頁，點選 **新增供應商**，建立個人供應商
4. 填服務位址、API Key 和協定：Anthropic Messages、OpenAI Chat Completions 或 OpenAI Responses
5. 在 **模型（每行一個）** 填入服務商提供的模型 ID，再點選 **儲存**
6. 回到 ZCode，選擇和測試該供應商/模型

邊界：這裡只管理個人供應商與模型 ID。帳號登入、預設模型、代理、MCP、Skills 和進階模型能力參數仍在 ZCode 管理。其他來源的個人供應商可能只讀。

![測試版 ZCode：選擇應用、新增與編輯個人供應商](images/12-zcode-providers.png)

圖中 ① ZCode 應用；② 新增個人供應商；③ 已儲存的位址、協定和模型；④ 編輯入口。

![測試版 ZCode 編輯表單：API 位址、協定與逐行模型 ID](images/13-zcode-edit.png)

圖中 ① API 位址；② 編輯時留空可保留原 Key，新建則由你本人填寫；③ 協定；④ 模型 ID，每行一個；⑤ 儲存後回 ZCode 測試。範例模型名不代表你的服務一定提供這些模型。

編輯已有供應商時，空白 Key 表示保留現有 Key；刪除前會確認。遇到外部修改衝突時，取消編輯、重新整理後重新開啟，不要強行覆蓋。設定目錄有自訂時，按 [ZCode 專項說明](../zcode.md) 核對，不猜目錄。
