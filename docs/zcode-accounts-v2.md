# ZCode 账号流程 V2

范围：`LOONG-ZCODE-ACCOUNTS-V2.0`，Z1 / U1–U6。此文记录已确定的产品契约；本分支当前只有恢复实施文档，新增实现、测试和原生验收均待完成。

## 用户流程

| 界面 | 行为 |
| --- | --- |
| U1 登录账号 | 常驻添加账号、保存本机登录、`.zsb` 导入、加密备份；显示名可改，稳定身份去重。账号库管理不要求已识别客户端；本机捕获和切换保留独立兼容条件。 |
| U2 官方登录 | 选择 BigModel / z.ai → 官方浏览器授权 → 脱敏身份与个人项目 → 准备 Start / Coding 连接 → 明确保存 → 再添加一个。添加不改变客户端当前账号。 |
| U3 导入 | 口令解密 → 逐项预览选择 → 明确授权向对应官方平台核验 → 逐能力结果 → 保存完整所选会话。重复默认保留，可明确更新；新候选未完成时保留旧有效记录。 |
| U4 备份 | 选择账号 → 说明范围 → 口令及确认 → 保存加密 `.zsb` → 持久写入并认证回读后报告成功。首版仅承诺原环境恢复。 |
| U5 手动切换 | 原生预检 → 具体影响确认 → 准确实例正常退出 → 保护当前身份与恢复点 → 最小字段写入 → 回读 → 重启 → 报告本地事实。复用原请求 ID 和恢复记录。 |
| U6 API 配置 | 保留已有单条供应商配置，独立于登录账号；API Key 不生成 OAuth 身份。本版不增加批量 API 导入。 |

官方 Coding Key 已存在时可复用；保存前说明凭据用途。创建缺失 Key 必须针对当前账号、family、个人项目、名称 `zcode-api-key` 取得该次明确同意，并提供官方撤销入口。暂不创建保留可恢复的待完成状态；有效 Start 连接不受 Coding 待完成影响。远端创建可能成功而本地响应/保存失败时，先查询原操作和原项目，不能重复 POST 或自动删除 Key。

取消、超时、重复点击、窗口离开和迟到结果不得替换较新的流程。保存已完成而响应丢失时，查看原结果，不重放保存。账号管理不默认调用模型或消耗配额。

## 身份与能力

`accountIdentity` 是本地凭据槽标识，不是上游授权证明。OAuth 回调的认证身份、包声明的展示身份、业务 token、Start JWT、Coding Key 必须分别表达来源与结果。保留用户明确选择的完整会话，不拼接不同包字段；业务 token 失败不自动否定可独立使用的 JWT / Key。

有效导入不一律要求逐人重登。曾将缺少额外同人证明推导成必须重登，这一推断被官方消费代码反证，不作为产品限制。包解密成功、本地 JWT 解码、缓存槽相同也不能冒充上游身份核验。网络超时是未知，不能写成凭据已过期；额度 0 与未知不同，各套餐、单位、窗口和更新时间分别显示。

`.zsb` 沿用外层 v1 / 内层 v2，10 MiB / 50 条上限，兼容 pjpv 固定格式。内层加密可能绑定原系统、用户或 home；不可解时报告原环境不兼容。备份不含设备 ID、机器密钥、项目历史或其他 LoongPort 秘密，不产生明文中间文件。

## 复用边界

基线为 [beta.3](https://github.com/SailingLoong/LoongPort/tree/4a26a0c2d0f095ae4b4ad13f4bfe8165d9bb570e)。现有 `zcode_accounts`、`SecretSession`、`VaultContext`、`OwnedFile`、catalog、transaction 和恢复日志继续拥有秘密及原生写入。UI 沿用现有 Radix / Tailwind 组件；业务状态与资格由后端给出。

- [官方 ZCode 固定源码](https://github.com/zai-org/ZCode/tree/29628c9acdb81b703bbd4080c207a0e7ce5e276e)：CLI init/poll、z.ai 业务 token 归一化、个人项目/Key 准备、官方凭据消费和套餐契约。
- [pjpv/zcode-switch 固定源码](https://github.com/pjpv/zcode-switch/tree/f34225686dfef05d84c256a56f868719248f15ff)：完整 session、包格式、加密导出与额度解析；保留既有 MIT 说明。
- 固定官方 provider 未实现 refreshToken 交换时，不发明刷新端点。原生激活沿 beta.3 精确 macOS 构建门禁；Windows、未知构建和在线推理不能以单元测试替代验收。

本版不含 WorkBuddy / CodeBuddy、跨 family 自动切换、团队账号、自动领取、自动轮换、设备重置、系统 CA、会话转公网 API 或跨机迁移承诺。已有 4.x 通用配置生命周期不接管 ZCode 原生账号。

## 验证与交付

新候选必须重新通过受影响测试与独立审查。纯核心 harness 必须编译产品真实模块；运行态/命令需验证实际进入编译图，不能把被 cfg 排除后的成功算覆盖。UI 检查取消、重复、结果恢复和列表刷新。真实 OAuth / 新 Key / 模型调用及原生进程操作仅在实际动作得到许可后执行。

源码检查点与交付状态记在[既有交付清单](zcode-quick-account-v1-delivery.md#v2-恢复实施与源码检查点)，具体任务见[恢复实施计划](superpowers/plans/2026-10-06-zcode-v2-recovery.md)。历史候选测试不替代本分支的新证据；文档检查点不代表新增功能已完成。
